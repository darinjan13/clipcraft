# Phase 7 Checkpoint 1I: WF17 Cloudflare Request Reconciliation

## Final Status

**WF17_BLOCKED_RUNTIME**

WF17's executed branch and response boundary were isolated. The prior HTTP 400
was not generated by a legacy WF17 branch: live `TEXT_EXECUTION_MODE=internal`
selected `ClipCraft Text Execute`, which called the private backend endpoint.
The backend access log recorded HTTP `422`. Existing backend code can produce
that same safe `422/AI_EXECUTION_FAILED` shape both for request-model
validation and when Cloudflare HTTP 400 is mapped to `invalid_request`.
Because the custom node discarded the backend safe message and status, the
persisted execution cannot prove which of those two sub-origins occurred.

The response boundary was corrected to preserve safe status/source
classification and non-retryable behavior. A deterministic no-provider WF17
preparation harness passed. No production job was created and no second live
provider probe was attempted.

## Exact Root-Cause Statement

The proven root cause is an observability and error-normalization loss at the
WF17 custom-node boundary: backend HTTP status and safe error message were
discarded, so a backend 422 was presented to WF17 as generic
`AI_EXECUTION_FAILED` with an inferred 400 status. The remaining distinction
between FastAPI request validation and backend mapping of Cloudflare HTTP 400
cannot be resolved from retained evidence without exposing or replaying the
provider request. No malformed field, invalid model ID, legacy branch, or
execution-mode mismatch was proven.

## Minimal Fix

Changed only WF17-related response handling:

- `n8n-custom-nodes/n8n-nodes-clipcraft/src/shared/clipcraftInternal.js`
  - added safe `AI_REQUEST_INVALID` classification;
- `n8n-custom-nodes/n8n-nodes-clipcraft/src/nodes/ClipCraftTextExecute/ClipCraftTextExecute.node.js`
  - preserves backend status code;
  - classifies `422` with safe `request is invalid` as
    `internal_validation`;
  - classifies other 422 failures as provider-originated;
  - preserves safe messages only;
- `workflows/17-ai-generate-text.json`
  - `Evaluate Provider Result` now honors `response.retryable === true`, so
    non-retryable validation/provider failures do not retry.

No caller, output shape, word-count logic, revision limit, provider mode,
WF03, WF04, database, renderer, TTS, or frontend contract was changed.
